Lesson 2.2: Gradient Descent

Why Gradients?

Almost every ML algorithm reduces to an optimisation problem: find the model parameters θ that minimise a loss function L(θ). Gradient descent is the workhorse algorithm for solving these problems at scale. Understanding it from first principles is non-negotiable.

Gradient descent does not find the globally optimal solution in general. For convex problems (like linear regression) it does. For deep networks it finds a good local minimum — and in practice, good local minima generalise well.

The Gradient

For a function of one variable, the derivative f′(x) tells us the slope — the rate and direction of steepest increase. For a function of many parameters (a model with millions of weights), the gradient ∇L(θ) is the vector of partial derivatives — one per parameter — each measuring how the loss changes as that parameter changes.

The key property: the gradient points in the direction of steepest increase. To minimise loss, we move in the opposite direction.

The Update Rule

The gradient descent parameter update at step t is:

θ ← θ − α ∇θ L(θ)

where α (alpha) is the learning rate — a scalar controlling step size. At each iteration we compute the gradient of the loss with respect to all parameters, then nudge every parameter slightly in the downhill direction.

Learning rate too highLearning rate too lowLearning rate just right
Overshoots the minimum; may divergeConverges but very slowlyConverges efficiently

Variants of Gradient Descent

Batch GD

Compute gradient over the entire training set. Exact but very slow for large datasets.

Stochastic GD (SGD)

Compute gradient on one example at a time. Fast and noisy — the noise can help escape local minima.

Mini-batch GD

Compute gradient on a small batch (32–256 examples). The industry standard — balances speed and stability.

Implementing Gradient Descent for Linear Regression

import numpy as np

def gradient_descent(X, y, lr=0.01, epochs=1000):
    """
    X: (n, p) feature matrix (with bias column)
    y: (n,) target vector
    lr: learning rate (alpha)
    Returns: learned weights w
    """
    n, p = X.shape
    w = np.zeros(p)          # initialise weights at zero

    loss_history = []

    for epoch in range(epochs):
        # Forward pass: predictions
        y_hat = X @ w          # (n,) predicted values

        # Compute MSE loss
        residuals = y_hat - y  # (n,)
        loss = (residuals ** 2).mean()
        loss_history.append(loss)

        # Compute gradient: dL/dw = (2/n) * X^T (y_hat - y)
        gradient = (2 / n) * (X.T @ residuals)

        # Update weights
        w -= lr * gradient

        if epoch % 100 == 0:
            print(f"Epoch {epoch:4d}  Loss: {loss:.4f}")

    return w, loss_history

# Example usage
np.random.seed(42)
n = 100
X_raw = np.random.randn(n, 1)
y = 3 * X_raw.squeeze() + 2 + np.random.randn(n) * 0.5

# Add bias column
X = np.hstack([np.ones((n, 1)), X_raw])

w, history = gradient_descent(X, y, lr=0.1, epochs=500)
print(f"\nLearned: intercept={w[0]:.2f}, slope={w[1]:.2f}")
# Should be close to intercept=2.0, slope=3.0

The Adam Optimiser

Vanilla gradient descent uses a fixed learning rate for all parameters. The Adam optimiser (Adaptive Moment Estimation, Kingma & Ba 2015) adapts the learning rate per parameter by tracking the first moment (mean gradient) and second moment (uncentred variance). It is the default choice for training deep neural networks.

import torch
import torch.nn as nn

model = nn.Linear(1, 1)
optimiser = torch.optim.Adam(model.parameters(), lr=1e-3)

for epoch in range(1000):
    optimiser.zero_grad()          # clear previous gradients
    loss = criterion(model(X), y)  # forward pass
    loss.backward()                # compute gradients (backprop)
    optimiser.step()               # update parameters
