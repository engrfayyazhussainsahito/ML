Lesson 4.1: Bias–Variance Tradeoff

The Bias–Variance Decomposition

The generalisation error of any supervised model can be decomposed into three components:

Expected Error = Bias² + Variance + Irreducible Noise
  • Bias measures how wrong your model is on average — the error from incorrect assumptions in the learning algorithm (e.g. using a linear model for a non-linear problem).
  • Variance measures how much your model's predictions fluctuate across different training sets — the error from sensitivity to small fluctuations in the training data.
  • Irreducible noise is the inherent randomness in the data-generating process. No model can reduce this.
The bias–variance tradeoff is not a law of nature — it is a consequence of using finite training data. With infinite data, you can have low bias and low variance simultaneously.

Visual Intuition

High Bias (Underfitting)

A degree-1 polynomial fit to degree-3 data. The model is too simple — it misses the real pattern, performing poorly on both training and test data.

High Variance (Overfitting)

A degree-15 polynomial fit to 20 data points. The model memorises noise — perfect training performance but terrible test performance.

Good Balance

A degree-3 polynomial capturing the true underlying trend. Low training error and low test error.

Diagnosing with Learning Curves

A learning curve plots training and validation error as a function of training set size. It is one of the most useful diagnostic tools in ML practice.

import numpy as np
import matplotlib.pyplot as plt
from sklearn.linear_model import LinearRegression
from sklearn.preprocessing import PolynomialFeatures
from sklearn.pipeline import make_pipeline
from sklearn.model_selection import learning_curve

# Create a pipeline: polynomial features then linear regression
model = make_pipeline(PolynomialFeatures(degree=3), LinearRegression())

train_sizes, train_scores, val_scores = learning_curve(
    model, X, y,
    train_sizes=np.linspace(0.1, 1.0, 10),
    cv=5,
    scoring='neg_mean_squared_error'
)

train_error = -train_scores.mean(axis=1)
val_error   = -val_scores.mean(axis=1)

plt.figure(figsize=(8, 4))
plt.plot(train_sizes, train_error, label='Training error')
plt.plot(train_sizes, val_error,   label='Validation error')
plt.xlabel('Training set size')
plt.ylabel('MSE')
plt.legend()
plt.title('Learning Curve')
plt.tight_layout()
plt.show()

# High bias:     both curves converge at a HIGH error
# High variance: large GAP between training and validation curves

Reducing Bias and Variance

ProblemSymptomSolutions
High biasHigh training AND test errorMore complex model; more features; fewer regularisation constraints
High varianceLow training error, high test errorMore training data; regularisation (L2, dropout); simpler model; early stopping

Cross-Validation

Cross-validation provides a reliable estimate of test error using only the training set. In k-fold CV, the training data is split into k equal folds. The model is trained k times, each time using k-1 folds for training and the remaining fold for validation. The k validation scores are averaged.

from sklearn.model_selection import cross_val_score
from sklearn.ensemble import RandomForestClassifier
import numpy as np

model = RandomForestClassifier(n_estimators=100, random_state=42)

# 5-fold cross-validation
cv_scores = cross_val_score(model, X, y, cv=5, scoring='accuracy')

print(f"CV scores:  {cv_scores.round(3)}")
print(f"Mean:       {cv_scores.mean():.3f}")
print(f"Std dev:    {cv_scores.std():.3f}")
# The std tells you how stable the model is across folds
Never use cross-validation scores to tune hyperparameters AND evaluate the final model — you will get an optimistically biased estimate. Use CV for tuning and a held-out test set for final evaluation.
