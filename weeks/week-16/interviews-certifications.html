Lesson 16.3: Interviews and Certifications

The ML Interview Landscape

ML roles span a spectrum from research (novel algorithm development) to applied ML engineering (production systems). Each has a different interview style. Understanding which role you are interviewing for determines how to prepare. This lesson covers the most common interview formats and evidence-based preparation strategies.

ML System Design Framework

"""
Framework for answering "Design an ML system for X" questions.

Example: "Design a recommendation system for a streaming service."
"""

framework = {
    "1. Clarify requirements (5 min)": [
        "What exactly should be recommended? (movies, episodes, playlists?)",
        "What is the optimisation target? (clicks, watch time, retention?)",
        "Scale: users, items, requests/second?",
        "Constraints: latency budget, cold start, explainability?"
    ],
    "2. Define the ML task (5 min)": [
        "Formulate as: ranking, classification, regression, or generative?",
        "Define the label: implicit (clicks) or explicit (ratings)?",
        "Choose the evaluation metric: NDCG, MRR, Precision@k?"
    ],
    "3. Data pipeline (10 min)": [
        "What data is available? (user history, item metadata, context)",
        "How is it collected, logged, and stored?",
        "Train/val/test split strategy (temporal for rec systems)",
        "Feature engineering: user embeddings, item embeddings, context"
    ],
    "4. Modelling (10 min)": [
        "Baseline: popularity-based or collaborative filtering",
        "Candidate generation: matrix factorisation, two-tower network",
        "Ranking: gradient boosted trees or neural ranking model",
        "Cold start handling: content-based features"
    ],
    "5. Serving and monitoring (5 min)": [
        "Offline vs online inference?",
        "Latency: pre-compute candidates, approximate nearest neighbour",
        "A/B testing framework",
        "Monitoring: CTR, watch time, model drift"
    ]
}
